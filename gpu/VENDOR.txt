GoW3R rendering compatibility backports (2026-10-11), adapted from cuesta4/shadPS4:
  - CUSA01623/CUSA01715 1.02 video-arena profile: cache-image word 0x007cd918 is set to
    0x90000000 (2.25 GiB / 2304 MiB); the user's eboot.bin is never modified. The host direct
    memory budget defaults to 7104 MiB (5056 + the 2048 MiB required by this profile).
  - the established narrow-image readback path is retained. Image alias synchronization uses
    the eltutz backing/writer authority model, but only between matching GNM layouts (address,
    bit depth, samples, type, pitch, tile/array modes, bank swizzle and alternate tiling).
    Block-compressed images additionally require an exact pixel format and covering extent;
    this avoids the broad same-address copy that corrupted CUSA01623 character textures.
    GOW3R_ALIAS_SYNC=0 provides a diagnostic fallback without changing the default profile.
  - asynchronous first-use graphics-pipeline skipping is disabled by default for GoW3R. The
    previous fast profile deliberately omitted geometry draws while Vulkan pipelines compiled,
    which could leave complex Titans and distant LOD passes incomplete during their first scene.
    Shader/SPIR-V caching remains enabled, so subsequent starts retain the compiled shader work.
  - the complete tiling-region mapping from cuesta4 commit 83352ea is adapted to the base port's
    threaded recorder: each mip uses its real aligned guest offset, tile-shaped dispatch and
    coordinated macro-to-micro tail addressing. Applying only the address-function switch had
    corrupted distant CUSA01623 LOD/background textures because invocation coordinates still used
    the old linear traversal. The inherited exact-image lookup fast path is retained; invalidating
    it on every registry topology change regressed stable character and weapon textures.
  - host-visible texture payloads are copied to device-local memory before the detiling compute
    pass, with explicit transfer-to-compute and compute-to-transfer range barriers. This follows
    the current cuesta4 path and removes timing-dependent reads observed while Pos050/Gaia assets
    are streamed; the texture trace had previously hidden most of the corruption by delaying the
    GPU thread. Large 2048x2048 BC3 surfaces remain on the stable direct-input path because the
    older buffer-cache lifetime model in this snapshot introduces diagonal bands when staging
    those surfaces. GOW3R_STAGE_LARGE_BC3=1 reenables their staging for diagnostics; smaller BC3
    and foliage/particle uploads keep the device-local path.
  - factor-scaled MIN/MAX blend uses the eltutz two-draw squaring pass; the older shader-only
    approximation squared the source but left the destination unscaled. Shader binary cache
    version 8 prevents reuse of binaries generated by that approximation.
